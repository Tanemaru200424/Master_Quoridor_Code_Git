# Quoridor(縮小版) 解析プロジェクト

後退解析(先手の勝敗と決着までの手数)、到達可能配置解析、表参照の3つのプログラムを、
`make` 1回でビルド・実行・検証できるようにしたものです。

## ディレクトリ構成

```
Project/
├─ src/
│   ├─ common/               共通部分 (ZDD, 局面操作)
│   │   ├─ zdd_quoridor_board_only.hpp / .cpp
│   │   └─ posi_quoridor_board_only.hpp / .cpp
│   ├─ retrograde-analysis/  後退解析    (main_quoridor_retrograde_NLBW.cpp → quoridor_retrograde.o)
│   ├─ reachability/         到達可能解析 (main_quoridor_reachable_NLBW.cpp → quoridor_reachable.o)
│   └─ lookup/               表参照      (main_quoridor_lookup_NLBW.cpp    → quoridor_lookup.o)
├─ bin/
│   ├─ quoridor_retrograde_exe, quoridor_reachable_exe, quoridor_lookup_exe
│   └─ 参照データ (N=3, L=4 までの後退解析・到達可能解析の表 *.bin)
├─ results/                  make run / verify が作る出力先 (N<N>L<L>/ ごと)
├─ Makefile
└─ ReadMe.md
```

## 最初に1回だけ必要な作業

`N`(コマ盤面の1辺のマス数)はコンパイル時定数なので、Makefileの `N=` で切り替えるには
`zdd_quoridor_board_only.hpp` の `N` の定義を `-DQUORIDOR_N` で上書きできる形にする必要があります。

```
make patch-header
```

(`static constexpr int N = 5;` を、`QUORIDOR_N` が未定義なら5を使う形に1か所だけ書き換えます。
何度実行しても結果は同じです。未対応のままビルドすると、同じ案内がエラーとして表示されます。)

## 使い方

| コマンド | 内容 |
|---|---|
| `make` / `make build` | 3つの実行ファイルをビルドして `bin/` に出力 |
| `make run N=3 L=4` | N, L における 到達可能配置解析 + 後退解析 を全 (L,B,W) 組合せで実行 |
| `make verify N=3 L=4` | 最初から全解析 → 表参照の整合確認 → `bin/` の参照データと比較 |
| `make compare N=3 L=4` | 既にある結果を `bin/` の参照データと比較するだけ |
| `make lookup-demo` | 初期配置を表参照プログラムで引く (`INIT_FEN="..."` で任意の配置) |
| `make clean` | オブジェクトファイルと実行ファイルを削除 (`bin/` の参照データは残る) |
| `make distclean` | `clean` に加えて `results/` も削除 |

`L` は盤上に置けるフェンス数の最大値で、ルール上使えるフェンス総数 M と同じです(偶数)。
片方のプレイヤーの手持ちは最大 L/2 枚です。`make -j2 run` で到達可能解析と後退解析を並列に実行できます。

### 主な変数

| 変数 | 既定値 | 意味 |
|---|---|---|
| `N`, `L` | 3, 4 | 解析するルール |
| `REF_MAX_N`, `REF_MAX_L` | 3, 4 | `bin/` に参照データがある大きさ。この範囲内のときだけ比較する |
| `ALLOW_NOREF` | 0 | 1にすると、比較できる参照データが1つも無くても警告だけで成功扱いにする |
| `INITIALIZE` | 1 | 1: 解析対象ファイルを削除して最初から / 0: 既存ファイルの続きから |
| `STOP_RULE` | `bound` | 後退解析の反復の終了条件 (下記) |
| `ITER_MAX` | 254 | 後退解析のITERの上限 (8bitエントリで表せる最大値) |
| `OPT`, `CXX` | `-O2`, `g++` | コンパイルオプション・コンパイラ |

## 実行の流れ

- **到達可能解析**: 初期配置(L=0)から前向きに伝播するので、L を 0 から昇順に処理。各 (L,B,W) で新規が0になるまで反復。
- **後退解析**: 終端側から逆算するので、L を大きい方から 0 へ降順に処理。各 (L,B,W) で `ITER=0,1,2,...` を自動でカウントアップ。
  1回の実行で `(L,B,W)` と `(L,W,B)` の両方の表を解くため、`B<=W` の組合せだけ実行する。
- ログは `results/N<N>L<L>/logs/` に保存される。

### 後退解析の終了条件について (重要)

従来のシェルスクリプトは「`ITER>0` で new が0なら終了」でしたが、これは**早すぎます**。
(L,B,W) の中に手数の欠番があるためです。たとえば N=3, M=2 の `L=0,B=1,W=1` は、
手数1の次が手数6で、手数2〜5の局面はこの表の中に1つもありません(深い値は L+1 側の子から飛び込んで付く)。
旧条件では ITER=2 で止まり、30局面が未確定のまま残ります。

既定の `STOP_RULE=bound` は、次の事実に基づく確実な条件です。
`new==0` の回は表が変化せず、未確定の局面に今後付く値は「判明済みの子の値+1」だけです。
したがって判明済みの最大手数を V とすると、`ITER >= V+1` で終了して取りこぼしはありません。
(旧条件は比較用に `STOP_RULE=or` で残してあります。)

## 検証について

- `make verify` は `results/N<N>L<L>/` を作り直して全解析を行い、生成された全 `quoridor_*_N<N>L*.bin` を
  `bin/` の同名ファイルとバイト単位で比較します。1つでも違えば終了コードは非0です。
- `N` が `REF_MAX_N` を、または `L` が `REF_MAX_L` を超える大きさでは、参照データが無いので比較はスキップされます。
- ファイル名には L, B, W が入りルール上のフェンス総数 M = L+B+W が決まるので、
  `bin/` に M=4 のファイルしか無い場合、`L=2` の検証は「参照なし」になります。
- 表参照の確認として、後退解析ログ中の「初期配置の手数」と、表参照プログラムが返す値が一致することも確かめます。

## 既知の注意点

- `src/lookup/main_quoridor_lookup_NLBW.cpp` の後手コマ位置の変換 `(w_pawn_pos/N)*(2*N-1) + (w_pawn_pos)` は
  `(w_pawn_pos%N)` が正しいです。後手コマが最上段(行0)にある配置(初期配置など)では偶然正しく動きますが、
  2段目以降にある配置ではエラーも出さずに**別の配置の結果を返します**。
- N が大きいと、全 L のZDD構築とテーブルでメモリ・時間が急増します。小さい設定で所要時間を見積もってから段階的に上げてください。
